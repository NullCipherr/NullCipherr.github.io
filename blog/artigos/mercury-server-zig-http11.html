PROJETO: MERCURY SERVER

Mercury Server: arquitetura low-level de HTTP/1.1 em Zig

Publicado em 09/04/2026 • Leitura estimada: 6 min

O Mercury Server nasceu com um objetivo direto: entregar previsibilidade operacional em um servidor HTTP/1.1 com baixo overhead e controle explícito de recursos. Em vez de abstrações pesadas, a base usa parser manual, workers fixos e métricas para guiar evolução incremental.

Decisões centrais de engenharia

  • Parser HTTP escrito manualmente para controlar limites de cabeçalho/corpo.
  • Pool thread-safe para desacoplar accept do processamento.
  • Timeout de leitura/escrita por conexão para reduzir risco de conexões presas.
  • Endpoint /metrics para visibilidade de requests, erros e latência média.
  • Proteção contra path traversal no servidor de arquivos estáticos.

Benchmark como ferramenta de produto

O benchmark oficial do projeto serve como referência de maturidade técnica, não como comparação superficial. O foco está em estabilidade de comportamento com parâmetros explícitos de carga e geração de artefatos reproduzíveis em benchmarks/results/.
